## 日常维护：使用站内管理平台

打开 [网站管理平台](/admin/)，使用 **MrLittleShark 对应的 GitHub 账号**登录。无需再次提供仓库访问令牌。账号权限保存在数据库的角色表中，修改个人资料不能获得管理权限。

网站分为两个维护层：**内容与社区由 Supabase 管理，外观与静态资源由 Hexo 构建**。日常发布课程、文章、资料和公告，保存后即可在网站读取；修改布局、脚本或样式时，再发布 Hexo 源码。

## 建立课程、文章与专栏

1. 在“内容库”选择“新建内容”，设置类型。课程单元、课程集合、分享文章、作者日志、资料、资源推荐、工具、专题模块、公告、作业与参考内容分别管理。
2. 填写名称、唯一地址标识、摘要、所属模块和专栏。地址标识使用英文、数字和短横线，例如 `mesh-quality-basics`。
3. 编写 Markdown 正文，补充来源、版本、完整示例和验收方法。课程不以命令罗列代替解释。
4. 上传图片后粘贴图片地址，或使用现有站内资源。封面字段填写图片 URL。
5. 先保存草稿并预览；检查无误后选择“保存并发布”。发布页地址为 `/read/?slug=地址标识`。

“所属模块”决定主题分类，“专栏 / 系列”用于组织连续文章。排序权重越小，目录位置越靠前。模块名称和导航名称分别管理：改导航不改变文章所属主题。

## 课程目录与章节导航

课程阅读页自动提供“首章、上一章、下一章、末章”。导航范围是**同一系列内已经发布的课程单元**，不包含草稿、归档内容或其他系列的文章。

1. 将连续课程的“专栏 / 系列名称”填写为完全相同的名称。
2. 按学习顺序设置“排序权重”，例如 10、20、30，为后续插入课程预留间隔。
3. 排序权重相同时，系统再按地址标识排序；需要明确章节顺序时使用不同权重。
4. 修改标题、排序或发布状态后刷新阅读页，检查相邻章节。首章的前向入口、末章的后向入口会自动停用。

“模块与专栏”可以统一重命名系列。只修改一篇课程的系列名称会使其进入另一组导航；改导航菜单显示名称则不改变课程归属。课程完成状态按稳定内容 ID 保存，日常改标题或排序不会创建新的课程记录。

## 课程案例下载与专题归属

编辑课程时，使用“专题与配套案例”区域维护下载入口。一个课程可以关联多个案例包；多篇课程也可以共用同一包，并在说明中分别写清需要打开的子目录和本课修改的文件。

1. 勾选相关专题：湍流、多相流、网格划分或动网格。课程仍保留原有系列与章节顺序。
2. 点击“添加案例下载”，填写名称、文件地址和使用说明。编辑或管理员可直接上传不超过 50 MB 的 ZIP；系统记录文件大小与 SHA-256。
3. 在核验说明中写明实际完成的检查，例如字典读取、网格检查、求解运行或解析解比较。保留日志才能使这些结论可以复查。
4. 保存后检查课程目录卡片、正文开头和相关专题的下载区域。仅删除下载入口不会删除共享文件；需要删除附件时，先检查其他课程是否仍在引用。

[专题学习](/topics/)以“专题模块”类型管理。现有四个模块可以修改标题、摘要、正文、封面和发布状态；其元数据 `topic_key` 分别为 `turbulence`、`multiphase`、`meshing`、`dynamic-mesh`，请保留这些关联标识。专题内的课程与案例由课程勾选项自动汇总。归档模块会隐藏专题内容，不会删除课程。

## 教学插图与出处

课程图片可点击放大，放大视图保留图注与来源。Wolf 讲义配图下方标注作者、分册、页码、原始链接与 CC BY-SA 4.0；裁剪图还注明处理方式。引用图用于解释原理，其坐标、工况和结论仍需结合原图理解，不能改写成本站新增计算的结果。

图源清单保存在 `tools/content/wolf-figures.json`，包含来源 PDF 哈希、裁剪范围、图片尺寸和文件哈希。替换插图时一起更新图注与清单，并检查亮暗模式下的色标和文字。课程正文采用 v2512 的术语、配置与操作。

## 分类资源推荐

[资源推荐目录](/recommendations/)用于整理外部文档、课程、源码、网格工具、可视化工具和学术社区。它与本站可下载的“资料”及较完整的“扩展工具”教程分别维护。

在内容库中新建“资源推荐”，设置“所属模块”为推荐分类，例如“官方文档”“教程与课程”“源码与开发”“几何网格”“可视化与数据”或“学术社区”；“专栏 / 系列”可统一为“资源推荐”。正文至少写清用途、适合的读者、阅读顺序、版本限制与资源链接。

元数据可采用以下结构；将示例链接替换为已核对的实际入口。

```json
{
  "external_url": "https://api.openfoam.com/2512/",
  "resource_type": "recommendation",
  "cost": "free",
  "source": "OpenCFD 官方 API 文档",
  "verification": "填写实际核对方式和访问限制",
  "checked_on": "2026-10-02"
}
```

`external_url` 保存外部入口，正文中也应提供可点击链接。定期复查链接与版本，收费服务和免费公开资料分别说明。遇到浏览器验证或页面无法读取时记录限制，不把“链接存在”写成“内容全部核验通过”。第三方社区的经验建议需要继续核对固定版本源码。

## 数学公式与代码

正文统一用 TeX 表达公式。行内公式写 `\( \mathrm{Re}=UL/\nu \)`，独立公式写 `\[ \nabla\cdot\mathbf{U}=0 \]`。预览中发现红色公式源文，应修正语法后发布。

代码必须放入带语言名称的代码块。常用语言是 `bash`、`openfoam`、`cpp`、`python`、`makefile`、`json`。不要把终端输出、C++ 和字典混在同一个未标注代码块中。

````markdown
```openfoam
PISO
{
    nCorrectors 2;
    nNonOrthogonalCorrectors 0;
}
```
````

图片应说明它是示意图、原资料图还是真实计算。真实计算图需要给出版本、网格、时刻和物理量单位。

## 上传与删除资料

“文件与图片”支持图片、PDF、ZIP、文本与常见 Office 文档，**单个文件不超过 50 MB**。上传后复制地址，插入课程，或点击“建立下载条目”，补全说明后发布。

上传位置是公开资料桶，文件上传成功即可以通过链接访问。草稿状态只控制内容目录和正文，不能把公开附件变成私有文件。只上传准备公开分享的资料。

删除资料条目会先移入回收站；删除存储文件是独立动作。删除附件前，检查其他文章是否引用同一个 URL。现有静态下载包由 Hexo 源码目录 `source-openfoam/downloads` 管理，替换后需重新构建。

## 删除、恢复与版本历史

- “移除”将内容送入回收站，访客不再能从内容服务读取。
- “恢复”将内容恢复为草稿，检查后重新发布。
- 每次正文更新均保留上一版本。打开“历史版本”，载入旧版后保存，会生成新的版本记录。
- 永久删除仅管理员可执行，同时删除对应评论与历史版本，界面会再次核对。
- 编辑采用版本检查。若另一个窗口已更新同一篇文章，保存会报告冲突，不会覆盖对方修改。

命令与字典页面有静态初始版本，并在浏览器读取后台的最新发布正文。归档后浏览器会显示归档状态；旧 HTML 可能仍存在于 GitHub Pages 或浏览器缓存中。需要从静态文件与搜索引擎缓存彻底移除时，还需删除对应 Hexo 源页面、重新发布并等待缓存刷新。

## 作业、公告与讨论

发布作业时选择“课程作业”，明确输入、运行步骤、应交文件和验收依据；若有截止时间，写明日期与时区。现有练习支持 **GitHub Issues 公开提交**，学生也可以在作业评论区贴提交链接。

公告选择“网站公告”，发布后自动进入公告目录。普通作者不能自行发布公告。

讨论中心无需登录即可阅读。GitHub 登录用户可以提出问题、回答和评论。问题作者可标记已解决；管理员或版主可置顶、关闭、隐藏和恢复主题。关闭主题后停止新增回复，隐藏内容由数据库规则限制访问。

每篇文章都可以独立开关评论区。在“讨论与评论”中管理回答和文章评论。管理员可在站点设置中暂停新增讨论。为控制重复发布，同一普通账号每小时最多新建 5 个主题、发布 40 条回答或评论。

## 管理员、编辑、版主与作者

| 角色 | 权限 |
| --- | --- |
| 管理员 | 全站内容、附件、社区、导航、角色与永久删除 |
| 内容编辑 | 内容建立、修改、发布、归档、附件维护、编辑历史 |
| 社区版主 | 讨论和评论审核、置顶、关闭与恢复 |
| 普通会员 | 提问、回答、评论、学习记录、撰写文章与日志草稿 |
| 禁止发言账号 | 保留公开阅读，停止新增社区内容与投稿 |

普通会员从[作者工作台](/studio/)保存文章草稿，由编辑审核发布。成员权限通过用户 ID 指定；已经参与社区的成员可从名单中选择。系统不允许移除最后一位管理员。

## 个人资料与学习记录

学校、研究方向和学习目标由账号本人读写；参与社区时使用公开显示名称。新版课程以稳定内容 ID 保存完成状态，支持跨设备同步。

旧版 28 讲与新版内容不一一对应。旧完成记录保留在原表中，但不会自动转换成新版完成记录。

## 修改外观与发布 Hexo

本地工作目录为 `E:\Hexo`。主要目录如下：

| 位置 | 用途 |
| --- | --- |
| `themes/foam-lab/layout` | 页面模板 |
| `themes/foam-lab/source/assets` | 样式、浏览器脚本与组件 |
| `source-openfoam` | 静态命令、字典、下载包与图像 |
| `tools/content` | 本次重构的内容源与可复现生成脚本 |
| `supabase/migrations` | 数据库结构和权限变更 |
| `supabase/tests` | 数据库权限验证 |

使用本地目录中的“启动学习网站.cmd”预览，确认桌面和手机显示正常后，运行“发布学习网站.cmd”。源文件同步至 GitHub 的 `foamlab-source` 分支，GitHub Actions 执行校验、Hexo 构建和 Pages 部署。

需要在终端手动执行时，在已安装 Node.js 的环境中运行：

```bash
npm ci
node tools/check-tex.cjs
npm run build
npx hexo deploy
```

发布器在同步时检测远端变动。遇到冲突应比较并合并源文件，不要强制覆盖远端修改。构建失败时检查 [GitHub Actions 日志](https://github.com/MrLittleShark/mrlittleshark.github.io/actions)。

## 字体、亮暗模式与界面规范

具体字号、行距、字体来源、对比度与手机排版规则见[字体与界面设计规范](/design/)。正文采用 Noto Sans SC，标题采用 Noto Serif SC；代码使用等宽字体，数学公式由 KaTeX 字体排版。中文字体子集和许可证在本站托管，不依赖外部字体 CDN，新增罕见字符由系统字体回退。

亮色、暗色和跟随系统选项保存在当前浏览器。调整 `typography.css`、`presentation.css` 或布局后，应分别检查长文、代码、公式、表格、表单和手机页面；不能只检查首页。不要在课程正文中逐段写入固定字号或字距，以免破坏统一阅读样式。

## 支持入口与收款码

管理员可在“站点与导航”下方的“支持入口与收款码”管理用途说明、微信与支付宝图片及启用状态。公开入口为[支持本站](/support/)。**当前未上传真实收款码，入口保持关闭。**

1. 准备本人愿意公开的真实收款码图片，格式为 PNG、JPEG 或 WebP，单张不超过 5 MB。
2. 在相应渠道选择图片上传，或粘贴已上传图片的 HTTPS 地址。上传成功后检查预览，并用对应应用核对收款对象。
3. 填写简洁的用途说明，至少配置一种有效图片后勾选“启用支持入口”，再点击“保存支持设置”。
4. 在公开入口检查图片、用途说明与手机显示。更换图片后重新核对；暂停时取消启用并保存。

这项配置只控制公开图片与说明，不代替支付平台，也不提供到账统计。图片上传到公开存储桶；关闭入口不会删除图片，需要删除时在“文件与图片”中操作，并确认没有其他引用。不得使用临时占位图冒充真实收款码。

## 备份与回滚

管理平台“导出与维护”可导出当前可访问的内容和站点设置。**JSON 导出只包含附件地址，不包含文件本体**，资料文件需要另外保存。数据库的完整备份、用户身份和存储桶在 Supabase 后台管理。

备份至少包含：内容导出 JSON、附件、`foamlab-source` Git 历史、数据库迁移脚本。课程初始导入脚本默认不覆盖已经存在的地址标识，因此重新运行初始化不会覆盖后台编辑。

账号认证参数位于 `source-openfoam/assets/auth-config.json`，这里只允许公开 publishable key。GitHub OAuth Secret 与 Supabase 服务端密钥只能保存在相应服务端配置中。

## 扩充内容时的检查顺序

1. 先查版本与源码依据，再选择最小示例。
2. 确认代码可以复制，参数有单位，字典能解释上下文。
3. 检查 TeX、图片、下载和站内链接。
4. 区分“源码核对”“编译通过”“短时运行”和“数值验证”。
5. 记录来源与修订原因，再发布到相应模块和专栏。
