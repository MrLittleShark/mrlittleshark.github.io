`runTimeControl` 根据计算中的条件执行动作，例如达到统计窗口后停止、残差达到目标后结束，或触发另一组输出。本课先运行一个容易观察的例子：从对象首次执行起经过 0.2 s，自动写出并结束计算。

## 1. 运行自动停止算例

下载 `05-autoStop.zip`，进入目录运行 `bash Allrun`。主 `controlDict` 仍写着 `endTime 0.5`，但后处理中的控制器会提前结束：

{{fo:05-autoStop:stopAfter}}

`conditions` 包含一个名为 `elapsed` 的条件。`type maxDuration` 检查经过的模拟时间，`duration 0.2` 是这一条件的阈值。`satisfiedAction end` 表示满足后正常写出并结束。

## 2. 为什么结束时间是 0.205 s

本例时间步为 0.005 s，控制器第一次执行发生在 0.005 s。它从这一时刻开始累计 `duration`，所以到 0.205 s 时正好经过 0.2 s。

日志末尾会出现：

```text
Time = 0.205
runTimeControl stopAfter output:
    maxDuration: elapsed
        Completed 0.2 out of 0.2
    maxDuration: elapsed condition satisfied
    Stopping calculation
    Writing fields
End
```

这种方式适合表达“从某阶段开始再运行多久”。若只需要固定的绝对结束时刻，在主 `controlDict` 中设置 `endTime` 就更直接。

## 3. 外层控制参数

| 参数 | 默认 / 取值 | 作用 |
|---|---|---|
| `conditions` | 必填命名子字典 | 列出检查条件 |
| `nWriteStep` | 默认 `0` | 条件满足后，在结束前额外写出的步数 |
| `satisfiedAction` | `end`、`abort`、`setTrigger` | 正常结束、异常终止或设置触发编号 |
| `trigger` | `setTrigger` 时填写 | 传递给其他功能对象的触发编号 |
| 执行控制 | 公共 `executeControl` 等 | 多久检查一次条件 |

正常提前结束使用 `end`。`setTrigger` 用于切换统计阶段，例如流场满足条件后才开始时间平均或增加输出频率。

## 4. 可组合的条件

| 条件类型 | 主要参数 | 典型用途 |
|---|---|---|
| `maxDuration` | `duration`、`resetOnRestart` | 某个阶段持续到指定时长 |
| `equationInitialResidual` | `fields`、`value`、`mode`、`timeStart` | 初始残差高于或低于阈值 |
| `equationMaxIter` | `fields`、`threshold` | 线性求解迭代次数达到阈值 |
| `minTimeStep` | `value` | 时间步缩小到给定值 |
| `minMax` | `functionObject`、`fields`、`value`、`mode` | 已有监测结果高于或低于给定阈值 |
| `average` | `functionObject`、`fields`、`tolerance`、`window`、`windowType` | 一段窗口内监测量变化满足容差 |

`functionObject` 引用已存在对象的名字，`fields` 则引用它公布的结果名。例如力系数控制先配置 `forceCoeffs`，再用其 `Cd` 等结果检查变化。

`equationInitialResidual` 与 `minMax` 的 `mode` 可取 `minimum` 或 `maximum`，对应低于阈值或高于阈值的判断。把阈值 `value` 与监测量的量纲配套填写。

同一个条件组可以通过 `groupID` 将多项条件组合为同时满足；不同组之间可以形成任一组满足即触发的逻辑。`active` 控制单个条件是否启用。逐项加入条件，并在日志中观察各项状态，组合的意义就容易判断。

## 5. 触发器怎样连接其他对象

被控制的对象可以设置 `controlMode trigger`，通过 `triggerStart`、`triggerEnd` 选择生效区间。需要同时限制物理时间时，使用 `timeAndTrigger`；满足时间或触发任一条件就运行时，使用 `timeOrTrigger`。

实际设置顺序是：先单独跑通监测对象，再确认控制条件读取到了它的结果，最后连接被触发的平均或输出对象。每一步都有对应文件或日志可以查看。

## 6. 从最简单的控制逐步扩展

五个层次分别是：经过固定时长结束；指定残差阈值；观察力系数窗口变化；把多个条件组成一组；满足条件后触发下一阶段。配套包提供第一个完整例子，后四类可按上表参数扩展到自己的问题。

提前结束前，选择的量应能代表当前任务。例如通道压降趋稳比只看某一个速度分量残差更接近最终目标；两相流则可能需要同时考虑液位、水量和周期变化。
